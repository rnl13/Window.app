# Window decision platform — implementation against source v22

## Audit and preservation
The actual current registered source was v22, newer than the Library projection v16. Existing /api/forecast uses Open-Meteo best_match plus MET Norway fallback, not direct DMI despite the historical site description. lib/kite-rules.ts powers the existing home/push scores. lib/window-decision.ts powers the explicitly synthetic /decision-lab, separate confidence and trip timing. Calendar uses D1, encrypted Google refresh tokens and optimistic revisions. Push uses D1 and web-push. History contains ERA5 wind summaries for 2016–2025 across four original spots. All these routes and their semantics remain intact. /ride is the new data-driven engine; home and lab link to it. Existing kite targets are ported into versioned local soft rules for the new engine; old notification thresholds are intentionally not silently reinterpreted.

## Implemented architecture
lib/intelligence/types.ts versions weather, sport/discipline, equipment, spot geometry, rules, forecast/observation snapshots, confidence, evaluation, feedback, errors and future model contracts. Discipline is a field of the sport configuration, not a switch in the engine. The 18 preset combinations and custom sports use the same evaluator. Inputs are SI, bearings clockwise from north and FROM. Sea bearing is the seaward coast normal; coastline is its tangent modulo 180. Tack is the sign relative to that normal (port/starboard convention documented in tests), not proof of the rider's actual sailing tack. Geometry is approximate and the Agger examples are user-derived; no launch surveys or bathymetry claims.

Conditions: trapezoidal weighted ranges plus AND predicates, boosts, penalties and hard blocks. Derived parameters include gust ratio, swell energy proxy H²T, circular wind/swell separation and swell/break separation. Generic range and predicate support covers wind, gust, swell, secondary swell, wind waves, tide, current, temperature, precipitation, daylight, duration and stability. Parameters not supplied by providers remain missing. Wave energy is a proxy, not a measured energy flux. Gustiness is not universally penalized; Big Air has its own ranges and level gate.

Merge order: SPORT → SPOT → PERSONAL. Later ranges replace earlier ranges by parameter; later soft rules replace earlier soft rules by stable rule ID. Hard rules accumulate and cannot be removed by an override, including one with the same ID. Dangerous spot sectors and daylight gates are separate. Hard rules use violation predicates: TRUE means blocked. Unknown data in a potentially relevant hard predicate produces unknown viability. Quality can remain high while viability is blocked; such results are labelled and ranked below eligible results. Score is never a safety certificate.

Decision: registered spots × enabled/equipped sports × contiguous hourly start times. Requires known manual travel times, setup/packing, minimum duration and available time. Scores all covered hourly samples, averages quality, and rejects any sampled hard violation. Returns the best interval per sport/spot, not just the highest single hour. Scores use IFS then GFS then DMI then AIFS as an explicit fallback order; WAM supplies swell/wind waves. It does not average forecasts into a claimed best estimate. This ordering is not learned skill. Approximate geometry and sparse hourly data limit near-shore advice. The UI connects eligible windows to the existing CalendarPanel.

## Data collection and privacy
D1 intelligence_batches retains immutable arrays of source-specific ForecastSnapshots for each requested registered spot, at most one fetch per hour in ordinary use. Cross-isolate races can produce additional snapshots. Each carries provider/model/family, requested/grid coordinates, retrieval and valid time, resolution estimate, weather and quality notes. No personal origin or journey coordinates are sent to weather providers. Collection is request-driven, not a scheduler: no visits means no new snapshots. The old /api/forecast does not write these new records.

modelRun and createdAt are explicitly null: the current hourly API response does not identify them. generationtime_ms is not a forecast creation time. Historical analyses cannot recover exact run skill from these records until a run-addressable provider is connected. No old forecast is treated as an observation. /api/intelligence does not claim successful storage when D1 fails.

Profiles, evaluations and feedback require authenticated account headers, same-origin writes, schema validation and opt-in. /api/rider re-evaluates selected immutable forecasts server-side before saving; it does not trust a submitted score. An evaluation embeds exact profile, rulesets, spot, engine version and forecast IDs. Session feedback embeds its evaluation, actual times, equipment, ratings and optional self-reported weather. Self-reported weather never becomes verified station evidence. No cross-user model training, email duplication, GPS tracking or analytics added. GET is account scoped; delete removes that user's profile and records. Public weather batches remain. Personal records are retained until deletion; no automatic retention expiration is implemented. Unsaved form edits are ephemeral. Saved profiles are reloaded after sign-in. Stored evaluations reconstruct why a score was given; travel feasibility is not yet retained as part of the saved evaluation record.

DMI raw wind observations are connected, time-stamped and stored in observation_records. Nearby station exposure is unverified and does not uplift confidence. Buoy, radar and satellite adapters remain interface-only. forecast_errors is migration-ready. The pure forecastError matcher requires verified quality, <=10km, <=30min, matched units, observed and valid times in the past, a pre-valid-time retrieval and known model run; error = observed minus forecast. It excludes session reports. No ingestion job calls it in production yet. Run stability and trend comparison are tested utilities, not live confidence evidence.

Confidence is independent and evidence-gated: unavailable without multiple comparable model families and known model runs; low under large disagreement/long horizons; medium only with the implemented gates. High is never produced by this new unvalidated model. IFS/AIFS count as one family. No percentages, satellite agreement, station verification or downscaling is fabricated.

## Not yet implemented
Verified observation matching and QC; satellite swath processing; run-addressed model collection; scheduled snapshots/backfill; automatic forecast-error jobs; learned bias/downscaling; trained models A/B/C; cross-user ruleset sharing/following; automatic travel routing; map-based geometry editing; arbitrary custom spots in /ride; per-sport rider levels; equipment size performance curves; full replacement of old home/push scoring. Ten-year history is preserved and extended with calendar-day wind aggregates across 2016–2025 in /ride. Wave distributions and forecast percentile comparison remain unavailable. Rules can be created/deleted in UI; existing range/rule editing and community version operations need an additional UX iteration.

## Validation
29 node:test cases pass including original calendar, push and decision suites and eight user-labelled calibration scenarios (not scientific ground truth). TypeScript noEmit passes. Production build passes. Real upstream check returned 600 snapshots across IFS/GFS/DMI/AIFS/WAM for Agger on 2026-09-13; this verifies that the configured model IDs and variables returned real data, not future availability or accuracy. Browser QA: page rendering, sport/equipment controls and forecast failure states were exercised. An insecure-context randomUUID error was fixed using crypto.getRandomValues fallback. The supervised browser preview could not retrieve the upstream forecast data; direct provider calls in the execution environment succeeded. A full authenticated browser round-trip for profile → evaluation → session and a real Google Calendar write were not verified. No real calendar event or notification was sent during this work.

Post-deployment QA: migrations are present in production, historical daily JSON returns HTTP 200 and unauthenticated profile access returns HTTP 401. Forecast request timed out from the test client. Removed shared in-flight promises (Workers request ownership), bounded provider fetch+body parsing to 8s and client requests to 30s. Full live recommendation success remains to be rechecked.
